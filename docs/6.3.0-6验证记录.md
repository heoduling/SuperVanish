# SuperVanish 6.3.0-6 插件侧预生成分配优化验证

日期：2026-11-11。只修改插件；未修改核心，未部署生产，未在运行核心中安装改写方法的 Java agent。

## 核验与方案

原审计属实：NoMobSpawn 的 PreSpawnerSpawnEvent 与基础自然事件共用 HandlerList，旧版启用特性后一直登记；准确核心只看共同表是否非空即创建基础事件、位置和弱引用，再由执行器筛选事件类型。

本版保留原预事件与原取消时机，仅在有在线隐身 UUID 时登记刷怪笼监听；最后一位显形或离线时撤下。隐身状态变更被取消则不刷新；离线保存隐身不独自触发登记，上线时恢复。启停与刷新使用同一短锁，既有 Folia 玩家业务仍在所属上下文执行，不新增调度器、缓存、配置键或运行依赖。

不直接换为 SpawnerSpawnEvent：准确核心可对刷怪笼矿车触发该事件，并将 getSpawner 设为空，无法通过该入口恢复原来源位置范围判定。自然刷怪、刷怪笼和骷髅马陷阱三段判定正文均保持原样。

改动类：SuperVanish、NoMobSpawn、FileVanishStateMgr；比较成品确认仅上述三个业务 class 改变。版本资源更新为 6.3.0-6。三个业务 class 以外没有新增运行类，测试用 MiniMessage JAR 为 testRuntimeOnly，不打入插件。

- 独立 JAR 描述、Folia 声明、主类、CRC、路径和哈希校验通过。

## 准确核心与真实流程

核心为 Shiroha/mizuki 26.2-DEV-96ca96b，启动 JAR SHA-256：19BAC68BDD71810A4417B69ACDC4B82F41A3E4D80065075F3D42AE87179F2B85。两版均使用该未修改核心、Java25、四个 tick 线程、相同导入地形、相同 DP 和配置，以及两个协议 776 客户端。11 个插件包括 WorldGuard 修改版9、WorldEdit、PhantomControl 2.1.1-4、PlugManX 3.1.0-Beta.2 和测量观察插件。

旧版、新版首次对照与新版两次维护复测各 16 条业务断言全部通过：原生 BaseSpawner tick 在仅隐身玩家时不产生实体，混合可见玩家和仅可见玩家时生成；三个场景均保留 200 tick 刷怪延迟。另通过真实 API 分发检查自然刷怪与骷髅马陷阱，接受/取消隐身请求，以及真实在线索引创建/移除钩子。原始记录中的实体出生数会受随机候选影响，只断言应允许/应阻止，不强求两版出生数相等。

维护复测完成：配置 false 时三个监听均撤下；true 时自然/陷阱监听各1、闲置预监听0；有人隐身时预监听1。隐身期间配置重载按原规则拒绝；真实隐藏玩家退出后预监听0，保留隐身重进后为1。普通配置重载及三轮 PlugMan 热卸载/加载均没有重复登记，卸载后相关监听为0，重载后可以重新登记与撤下。

跨区复测在实际两个不同 region ID 中并发完成128次隐身状态变更，最终监听回到0。单元代理覆盖原有邻近玩家不属于当前 owner 时的保守不取消分支；未声称在生产相同的边界刷怪笼位置实测该分支。矿车仍保留原预事件和来源位置参数，本次未单独搭建矿车生成实测。

首次跨区测试用768/512格间隔，记录显示两玩家仍处于 region0；因此该次维护测试失败并保留失败结果。增大到8192格并等待实体所属上下文后独立复测成功。随后旧控制器在配置重载仍执行时过早提交卸载，触发原有维护屏障并导致测试失败；改为等待真实 SuperVanish Folia ready 日志后，新一轮完整维护验证通过。两次均未修改插件来迎合测试。新版首次运行的六个性能窗口在这个维护失败之前已全部结束并被分别校验，所以仅采用其完整性能窗口，不将失败进程整体标成全通过。

热卸载只断言真实登记与业务恢复。本轮观察插件直接链接了 SuperVanish 类型，不能用它证明旧 classloader 回收，故不作该项宣称。各隔离 JVM 正常关闭。
